System Overview

From Camera to Perch in One Pipeline

The full stack runs onboard. A Raspberry Pi 5 with a Hailo AI Hat+ handles segmentation inference, candidate scoring, and visual servoing. Velocity commands are shipped over UDP to a Docker ROS container driving the flight stack.

🟦 Pi OS Side

  • Nicla Vision streams JPEG frames + ToF distance over USB serial
  • YOLOv8m-seg (.hef) runs at 10 fps on the Hailo AI Hat+
  • ByteTrack assigns persistent IDs across detections
  • Mask extraction → distance heatmap → skeleton → candidate scoring
  • 20-second warmup clusters candidate points and locks the final perch point
  • KLT tracker (FAST+Harris+Lucas-Kanade) tracks the point in real time
  • Pixel error + ToF packed as JSON and sent over UDP on port 5005

🟧 Docker / ROS Side

  • udp_receiver_node listens on port 5005, publishes /perch/error_x, /perch/error_y, /perch/tof
  • perch_controller_node runs a three-stage state machine: ALIGNING → APPROACHING → PERCHING
  • OptiTrack provides absolute odometry over VRPN
  • Proportional corrections issued at 1 Hz as absolute position setpoints
  • Perching trajectory: drop 0.40 m below branch, climb 0.60 m above to engage gripper
This thesis presents the development of an autonomous perching system for a small UAV. The system combines instance segmentation, feature tracking, and image-based visual servoing (IBVS) into a pipeline that runs entirely onboard without relying on external compute. A YOLOv8m-seg model is trained on a branch detection dataset, converted to HEF, and deployed on a Raspberry Pi 5 with a Raspberry Pi AI Hat+ for real-time inference at the edge. A postprocessing pipeline identifies and scores branch candidates, locks onto the most consistently detected perch point, then hands off to KLT-based tracking. The pixel error is sent over UDP to a ROS node in Docker, which drives the UAV through alignment, approach, and the final perching maneuver.
Detection Pipeline

From Raw Frame to Perch Point

Four postprocessing stages transform the raw segmentation mask into a precise perch point candidate. The pipeline runs on every frame during the 20-second warmup, then hands control to the KLT tracker.

Stage 0

Hailo Raw Output

Raw segmentation mask and bounding box from the quantized YOLOv8m-seg model running at 10 fps on the Hailo AI Hat+. No postprocessing applied.

Stage 1

Mask Extraction

Per-pixel confidence thresholded at 0.5 to produce a clean binary mask isolating the branch from the background.

Stage 2

Distance Heatmap

Euclidean distance transform on the binary mask. Pixels further from branch edges score higher — they sit at the thickest, most stable part of the branch.

Stage 3

Bitmask Skeleton

Medial axis skeletonization reduces the branch to a single-pixel centerline. Candidate points are restricted to this line.

Stage 4

Candidate Scoring

Weighted combination of model confidence (0.4), distance from center (0.35), and detection size (0.25). Filters remove vertical branches, out-of-size detections, and low-confidence outputs.

Stage 5

Full Pipeline

All stages combined — segmentation overlay, skeleton, and the single best candidate point rendered on the live camera feed during the warmup period.

IBVS

Image-Based Visual Servoing

Once the perch point is locked, the detection model shuts down. KLT optical flow tracking takes over and the IBVS computes pixel error between the tracked point and the frame center, which drives the UAV directly.

Stage 1

Feature Extraction

FAST detector followed by Harris corner response ranking extracts the strongest, most trackable corner features in a local region around the locked perch point.

Stage 2

KLT Tracking

Lucas-Kanade optical flow with pyramidal representation tracks the features across frames. The perch point position is estimated from the stored feature offsets relative to the reference frame.

Stage 3

Controller Output

The yellow arrow shows the error vector between the estimated perch point and the frame center. Arrow length is proportional to error magnitude. This error is sent as the IBVS control signal.

Stage 4

Full IBVS Pipeline

Combined view: KLT features (green), tracked perch point (red circle), and control error arrow (orange) all overlaid on the live camera feed.

Perch Mission

ALIGNING → APPROACHING → PERCHING

The full mission runs from a single launch command. OptiTrack provides odometry and the perch controller drives the UAV through all three stages before executing the gripper maneuver.

Flight

Third-Person View — Full Perch Mission

Third-person view of the UAV during the complete perch mission inside the indoor test arena. The UAV starts 3–4 m from the branch, aligns, approaches, and executes the perching maneuver without any manual intervention after launch.

Result

Successful Perch

The UAV drops 0.40 m below the perch point and sweeps upward 0.60 m to drive the passive spring gripper into the branch and engage it. The motors cut and the UAV holds its position on the branch.

📐 Stage Details

  • ALIGNING — pixel errors mapped to y/z corrections at 1 Hz; transitions when combined error < 10 px
  • APPROACHING — fixed forward steps along x while holding y/z; falls back to ALIGNING if error drifts > 20 px
  • PERCHING — triggered when ToF < 200 mm; two-leg trajectory: drop 0.40 m → climb 0.60 m

📊 Recorded Mission

  • ~39 seconds of perch controller activity from bag file
  • Initial combined pixel error ~60 px, converges to < 10 px over 20 s
  • X-axis advances from ~0.2 m to ~0.7 m during approach
  • Y and Z remain stable throughout approach phase
  • Perch maneuver visible as sharp altitude drop then climb in OptiTrack data
Hardware

Platform

Built on a 7-inch carbon fibre frame. All perception and control runs onboard.

Frame
7" carbon fibre (GEPRC MK4)
Motors
T-Motor F90 2810 × 4
Flight Controller
SpeedyBee F405 (MAVLink)
Onboard Computer
Raspberry Pi 5 (8 GB)
AI Accelerator
Hailo-8 AI Hat+ (10 fps)
Camera + ToF
Arduino Nicla Vision (2MP + VL53L1X)
Gripper
Custom 3D-printed passive spring (PETG)
Localization
OptiTrack (VRPN over LAN)
Model
YOLOv8m-seg → HEF (int8)
Training
1365 imgs, SAM3 annotation, 300 epochs
ROS
Noetic in Docker (uav_ros_stack_binary)
Communication
UDP JSON on port 5005 (Pi OS → Docker)
